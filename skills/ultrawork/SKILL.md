# SUPER mode

On explicit activation, include `SUPER MODE ENABLED!` after any host-required opening. Reading or discussing this skill does not request its execution. SUPER activation persists for the session; a follow-up does not restart a workflow.

The host handles activation, command aliases and native-mode selection. Discussed or quoted workflow names are not execution requests. `/stop-continuation` suspends automatic SUPER continuation in this session without clearing its records. A job result, reminder or ordinary follow-up is not `/resume-continuation`; do not revive suspended work on its authority.

The selected model profile owns ordinary working methods; OMP owns tools, permissions, approvals and native modes. Follow the host's selected mode, settings, tool gates and thinking effort without adding competing orchestration or QA rules or replaying activation. Plain SUPER selects no specialised workflow or native execution keyword.

## Goal ownership

For plain SUPER, use the OMP-native goal already created by the interactive invocation route. Existing active, paused or budget-limited goals retain ownership; paused work requires explicit user direction before resuming. A recognised specialised invocation never enters the plain native-goal route, including when workflow pointers are disabled. RPC and programmatic activation alone do not create a goal; the client must use OMP's native goal API. Do not infer goal creation from this policy or create a second goal, notepad or ledger for an ordinary task.

Explicit durable workflows keep their own state instead of adding a competing native goal:

- `/super-plan`: a decision-complete plan, without product implementation.
- `/super-run`: a selected plan, Boulder ownership and task/evidence ledger.
- `/super-loop`: multiple goals, dependencies and verified checkpoints.
- `/super-graph`: a dependency graph and node recovery records; use an owning loop or execution goal when present.
- `/super-research`: research claims, source evidence and a cited deliverable.

Read a specialised skill only when that workflow is requested or its specific artifact contract is needed. Bare SUPER does not select any of them. The selected workflow owns its artifacts and continuation. Shared loop-format state does not switch standalone research into loop execution. Resume existing state rather than creating another record of the same objective. Child assignments do not inherit SUPER activation or ownership of the parent workflow.

Load `skill://browser` for page interaction, `skill://ultimate-browsing` for blocked/incomplete sources, or `skill://computer-use` for native GUI work. Follow that skill's routing, authorization and evidence contract; pass applicable references explicitly to workers rather than assuming inheritance.
